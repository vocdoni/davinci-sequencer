# L1 blob DA proof of concept

DAVINCI publishes its per-batch data as Ethereum L1 blobs, and the settlement on OP Mainnet proves that data
through the L1 beacon root, so OP never needs blob access.

Chain of trust checked by `BlobDAPoC.settle`:

1. `4788(l2Timestamp)` on OP returns the `parentBeaconBlockRoot` of that OP block's L1 origin, which is the root of the
   beacon block that carried the blob (posted one slot before the origin's L1 block).
2. The supplied beacon header hashes (SSZ) to that root.
3. Each KZG commitment is in the block body: a 17-node SSZ branch leads to `header.bodyRoot`.
4. The 0x0A precompile opens each commitment at `z = sha256(pid || rootBefore || com) mod BLS_MODULUS` to `y`.
5. `digest = sha256(com_0 || y_0 || ...)` is what the zkVM proof binds; the PLONK proof is verified with the
   existing `ZiskVerifier` (0x6781FFF50D615CB3F331CCD3Bdad3416d4ce0d5c on OP, reused, never redeployed).

The data stream `S` is embedded in blobs as cells `0x00 || S[31j..31j+31]` (4096 cells per blob, at most 6 blobs).

## Layout

- `contracts/` Foundry project (`src/BlobDAPoC.sol`, `test/BlobDAPoC.t.sol`).
- `driver/` Rust CLI `l1blob-driver`.
- `fixtures/` `beacon_sidecar.json` (real mainnet sidecar), `real_proof.json` (real PLONK proof),
  `settle_fixture.json` (generated by `driver fixture`: z, y, kzg proof and the driver's own settle calldata).

## Build and test (local only, nothing is broadcast)

```sh
export CARGO_TARGET_DIR=$HOME/.cache/davinci-l1blob-target
D=$CARGO_TARGET_DIR/release/l1blob-driver
(cd driver && cargo build --release && cargo test --release)
$D fixture                                  # writes fixtures/settle_fixture.json (offline)
(cd contracts && ~/.foundry/bin/forge test) # includes the end-to-end settle() through the real 0x0A precompile
```

Read-only checks against public endpoints (use a throwaway key file, never the real one):

```sh
$D --key-file ~/.cache/l1blob-throwaway/key.txt --op-rpc-file ~/optimism-rpcs.txt address
$D --op-rpc-file ~/optimism-rpcs.txt probe-op            # 4788 lookup on OP
$D verify-l1 --tx 0x<any recent L1 blob tx>              # beacon inclusion + header + n+1 parent root checks
$D --key-file K --op-rpc-file ~/optimism-rpcs.txt dry-run --scenario nf16-steady --fixture fixtures/real_proof.json
```

`dry-run` builds and signs the L1 blob tx (EIP-7594 v1 sidecar), runs the local KZG openings and prints
estimated costs. It never sends. The OP settle gas in it is an approximation; the real run measures it.

## Real run (the lead engineer; broadcasts on Ethereum and OP)

```sh
export CARGO_TARGET_DIR=$HOME/.cache/davinci-l1blob-target
D=$CARGO_TARGET_DIR/release/l1blob-driver
G="--key-file $HOME/optimism-privkey.txt --op-rpc-file $HOME/optimism-rpcs.txt"
(cd contracts && ~/.foundry/bin/forge build)

# 1. deploy on OP (writes driver/deployments-10.json, gitignored)
$D $G deploy-op --poc-artifact contracts/out/BlobDAPoC.sol/BlobDAPoC.json \
   --fixture fixtures/real_proof.json --verifier 0x6781FFF50D615CB3F331CCD3Bdad3416d4ce0d5c
POC=$(python3 -c "import json;print(json.load(open('driver/deployments-10.json'))['poc'])")

# 2. scenarios (post after the proof is ready, the default)
$D $G run --poc $POC --scenario nf2-steady  --fixture fixtures/real_proof.json --eth-usd 2500 --repeat 3 --out results/nf2-steady.json
$D $G run --poc $POC --scenario nf16-steady --fixture fixtures/real_proof.json --eth-usd 2500 --repeat 3 --out results/nf16-steady.json
$D $G run --poc $POC --scenario max6 --bytes 761856 --fixture fixtures/real_proof.json --eth-usd 2500 --out results/max6.json

# 3. "post during proving": send the L1 tx first, the proof is deemed ready 60 s later
$D $G run --poc $POC --scenario nf16-steady --post-delay-secs 60 --fixture fixtures/real_proof.json --eth-usd 2500 --out results/nf16-delay60.json
```

Other flags: `--l1-tip-wei` (default max(RPC suggestion, 0.001 gwei)), `--blob-fee-cap-wei` (default
max(3 x blob base fee, 0.0001 gwei); worst-case blob spend of a 6-blob tx at the floor is 0.00008 ETH),
`--op-tip-wei` (default 10000), `--no-proof` (skip the verifier call), `--l1-rpc`, `--beacon`.
The L1 tx is a type-3 self-transfer (value 0, no calldata, gas 21000, maxFee = 2 x base + tip).

## Reading the results

Each result file has the aggregate (`latency_ms`, `cost_eth` with min/median/max) and `runs[]`. Per run:

- `timestamps_ms`: `proof_ready` (start of the L1 build, or `l1_sent + delay`), `l1_sent`, `l1_included_block_ts`,
  `beacon_proof_ready`, `origin_ready` (OP's `L1Block.number()` reached the L1 block whose parent root is the blob's beacon
  block), `op_sent`, `op_included_block_ts`, `op_receipt_seen`.
- `latency_proof_ready_to_settled_ms`: `op_receipt_seen - proof_ready` (wall clock); the same up to the OP block
  timestamp is in `latency_proof_ready_to_op_block_ts_ms`. The OP origin lags L1 by about 7 blocks, so expect
  roughly 1 L1 slot for inclusion + ~1.5 min for the origin to catch up in the post-after-proof flow. With
  `--post-delay-secs` at or above that, the wait disappears and the latency is just the OP settle.
- `l1.metrics` / `op`: gas, effective price, blob gas and price (L1); gas, `l2_fee`, `l1_fee` (OP receipt) (OP); `cost_wei`.
- `total_cost_eth` / `total_cost_usd`: L1 blob tx + OP settle.
- `checks`: all must be `true` (inclusion proof, header vs beacon API, L1 block n+1 parent root, OP origin reached,
  4788 match, `Settled` digest and beacon root equal the local ones, follower rebuild of `S` from the beacon API).
  A failed check aborts the run with an error.

Blobs are pruned by beacon nodes after ~18 days; the 4788 ring buffer on OP holds 8191 entries (about 4.5 h of OP blocks),
which bounds how long after the L1 inclusion `settle` can still be called.
